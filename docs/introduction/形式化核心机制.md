# 形式化核心机制

本文描述 AgenticPD 的搜索模型与当前实现边界，不把路线图中的 GWTW、Doomed Runs 写成已具备能力。

## 流程与参数

物理设计阶段为：

$$
\mathcal{S}=(\mathrm{FP},\mathrm{PL},\mathrm{CTS},\mathrm{RT},\mathrm{finish})
$$

可调参数按所属阶段组织为 $\Theta=\prod_{s\in\{\mathrm{FP,PL,CTS,RT}\}}\Theta_s$。一次候选由完整参数字典 $\theta$ 表示，执行后的最终 QoR 为：

$$
Q(\theta)=(\mathrm{WNS},\mathrm{TNS},\mathrm{Area},\mathrm{Power})
$$

最终比较采用时序优先规则；中间 stage 指标是观测，不是最终评价。

## Trial、checkpoint 与合法分支

一个 trial 是参数、执行记录和产物证据的不可变快照。checkpoint $c=(t,s,m,h)$ 包含来源 trial $t$、完成阶段 $s$、artifact manifest $m$ 与上游参数 hash $h$。

对候选参数 $\theta'$，只有所有变更参数都不影响 $s$ 及其上游阶段时，$c$ 才兼容：

$$
\mathrm{compatible}(c,\theta',\theta)=\bigwedge_{p\in\Delta(\theta,\theta')}\min(\mathrm{affects}(p))>s
$$

兼容 checkpoint 可以复用上游 artifact，但复制、hash 验证和下游执行仍有成本；它不是零成本继承。不兼容 checkpoint 必须回退到更早阶段或 full restart。

## 搜索决策

当前优化器维护优化树与 trial 历史。Judge 根据历史摘要选择分支节点与起始阶段，Stage Agent 在合法参数范围内提出下游阶段的参数。执行器负责参数渲染、ORFS 调用和结果解析，Agent 不直接执行 shell 或 Tcl。

可将一次决策表示为：

$$
\mathrm{Action}=(\mathrm{parent},\mathrm{start\_stage},\Delta\theta,\mathrm{policy\ metadata})
$$

其执行顺序为：验证 action → 验证/恢复 checkpoint → 执行下游阶段 → 解析 QoR → 写入 trial、树和历史。

## 当前边界

- `Optimizer`、`JudgeAgent`、`StageAgent` 与 `OptimizationTree` 提供当前的 AgenticPD 搜索闭环。
- `TrialManager`、`CheckpointManager` 与 ORFS adapter 提供结构化记录、完整性验证和阶段执行。
- `LocalBackend` 可执行本地命令；`SlurmBackend` 仅为接口 stub。
- GWTW population scheduler、Doomed predictor、Pareto archive 与跨设计学习模型尚未集成到运行时闭环。
