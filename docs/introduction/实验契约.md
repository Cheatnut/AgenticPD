# 实验契约

本文定义当前 AgenticPD 实验记录与 QoR 比较的固定口径。实现或参数空间变更前，应先取得用户对本文档改动的授权。

## 环境与配置

- 常规优化入口由 `config.py` 的 `FrameworkConfig` 和 CLI 参数共同决定；每个 session 写入 `config_snapshot.json`。
- checkpoint fork 验证使用 `configs/experiments/checkpoint-fork.yaml`，其参数、动作、容差和验收条件由 YAML 声明。
- 正式跨环境 QoR 比较前应刷新 `environment_manifest.json`；环境 revision 的缺失必须在实验报告中说明。

## QoR 来源与单位

正式 QoR 唯一权威来源是 ORFS 的 `logs/<platform>/<design>/<variant>/6_report.json`。

| 指标 | ORFS key | 项目单位 | 优化方向 |
|---|---|---|---|
| WNS | `finish__timing__setup__ws` | ps（ns × 1000） | 越大越好 |
| TNS | `finish__timing__setup__tns` | ps（ns × 1000） | 越大越好 |
| Area | `finish__design__instance__area` | µm² | 越小越好 |
| Power | `finish__power__total` | W | 越小越好 |

当 JSON 不存在时，解析器可从 finish report/log 读取兜底值。兜底结果只用于兼容旧 ORFS 产物，不应与 JSON 来源结果混写为同等精度证据。

## QoR 比较

`utils.qor_is_better()` 使用时序优先规则：先比较 WNS，再比较 TNS，时序在容差内才比较功耗与面积。默认容差来自 `FrameworkConfig`：WNS 10 ps、TNS 50 ps；checkpoint fork 验证可由实验 YAML 使用更严格容差。

- 最终胜负只依据 finish 后的 QoR。
- 中间 stage 指标可作为搜索观测，不能替代最终 QoR。
- 流程失败或 QoR 不完整的 trial 不参与最终 QoR 比较。

## Trial 与 checkpoint 记录

当前运行时以 `TrialRecord`、`StageResult` 和 `CheckpointRef` 为记录边界。

- `TrialRecord` 保存随机 8 位十六进制 `trial_id`、状态、父 trial、branch stage、完整参数、参数差异、最终 QoR、环境/配置 hash 与 artifact 目录。
- `StageResult` 保存阶段状态、耗时、退出码、相对日志/报告路径、命令、起止时间、阶段 QoR 与失败信息。
- `CheckpointRef` 保存来源 trial、阶段、上游参数 hash、artifact manifest 与 SHA-256；复用前必须验证 manifest 并检查参数影响阶段。
- session 使用 `trials.jsonl` 作为追加索引，并在每个 trial 目录保存 `trial.json`。

## Checkpoint fork 规则

参数变更只有在不影响 checkpoint 阶段及其上游时才能复用 checkpoint。`ParamSpec.affects` 是该判定的唯一配置来源。

- `FASTROUTE_LAYER_ADJUSTMENT` 通过 `FASTROUTE_TCL` 在 floorplan 已被读取，因此影响 FP、PL、CTS、RT；CTS checkpoint 不可复用。
- `GRT_CONGESTION_ITERATIONS` 仅影响 RT；CTS checkpoint 可以复用。

checkpoint fork 的正式对照必须同时包含：不兼容参数被拒绝的阴性对照、兼容参数的 fork/full-restart QoR 对照、耗时比较、manifest 验证和日志脱敏检查。

## 预算与公平性

实验报告至少区分 full flow、stage run 和 wall-clock 耗时；失败、超时和被拒绝 fork 的成本语义必须明确。后续多策略比较应固定参数空间、设计集合、seed、预算和 evaluator，并保留 baseline。
